A count of zero is not automatically a zero-event measurement. A numerical cross section or upper limit is released only after the event unit, independence claim, sensitive window, exposure denominator, and observation opportunity are established.

The 95% policy

  • Eligible \(n>0\): report \(n/\Phi\) with the exact two-sided 95% Garwood interval.
  • Eligible \(n=0\): report no point estimate and no two-sided interval; report only the conventional one-sided upper limit \(-\ln(0.05)/\Phi=2.995732273553991/\Phi\).
  • Any failed gate, including no observation opportunity: leave every numerical field blank. Do not report \(\sigma=0\) and do not manufacture an upper limit.

Pre-campaign checklist

From the paper's Section VI, the six steps that a test plan should address before committing beam time:

  1. Characterize the work cycle on the bench: measure \(W_0\), \(t_s\), and the firmware/configuration identity from event-free iterations.
  2. Set the test configuration: match the flight firmware, clock, memory placement, and workload as closely as affordable; disclose any departure.
  3. Run a short pilot at the target flux: measure \(\lambda\) and compute \(B^*=({\sqrt{2W_0/\lambda}-W_0})/{t_s}\); deploy a portfolio weighted low.
  4. Check the active-time fraction: confirm the device is computing, not recovering. If the fraction is low, reduce flux or batch size.
  5. Log telemetry that reveals device state: a state-changed flag (not just a mismatch report) resolves whether each corruption was a new event or a re-observation.
  6. Report with the full provenance: configuration, flux, batch size, counting rule, and any deviation from the flight design.
