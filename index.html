Why this tool exists

Dynamic single-event-effect testing runs real code on a device while it sits in a heavy-ion beam, watching for crashes (SEFIs) that interrupt computation. Before you commit beam time, two questions matter: how much flux can the device take before it spends more time recovering than computing, and how long will it take to accumulate enough fluence to trust your results? Those two questions pull in opposite directions. More flux means faster fluence accumulation, but also more crashes. This tool turns that tension into one number, the flux to dial in, held fixed for the whole run, and how long you'll need at the beam for it.

Flux is the one lever this tool optimizes. Work-cycle timing is treated as fixed. Most test designs can't freely change it, and it's application-specific, not a property of any one device. Batch size, where a test happens to support it, is a separate, optional refinement covered by the application, not a dial this tool assumes you can turn.

Design levers, in order

  • Flux, the primary lever. Chosen once, held fixed for the whole run. This tool's formula is built around it.
  • Batch size, optional and secondary. Only relevant if your test architecture supports a tunable checkpoint interval. Refines throughput at a flux you've already chosen, and does not change the flux decision.
  • Storage medium, a real confirmed hardware effect. This campaign found statistically significant heterogeneity across FRAM configurations (p=0.0001), tied to a confirmed buffer-persistence mechanism that tracks storage medium (FRAM vs. SRAM), not clock rate or batch size. Match flight configuration where affordable, and disclose any departure. See Campaign evidence.
  • Clock throttling, a real lever, not a free knob. Changes the compute-to -telemetry ratio and the resulting work-cycle time, not just raw speed. A throttled build's real cycle time can differ substantially from an unthrottled one at the same nominal clock rate, which changes the θ a given flux actually delivers. See Model & caveats.
